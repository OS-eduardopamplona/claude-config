# Jira Conventions

- RDMST: a project automation overwrites the description about 15 seconds after an issue is created, replacing it with template text. Create the issue first, then set the description in a second call, and re-read it afterwards to confirm it held.
- A description is exactly three panels, in this order, each opening with its title as a bold paragraph: an `info` panel titled **Description** (context, goal, the options the owner decides between), a `success` panel titled **Acceptance Criteria** (a bullet list), and a `note` panel titled **Implementation Notes** (bullets, including dependencies on other teams). No headings outside the panels.
- Write it with the Atlassian MCP `editJiraIssue` and `contentFormat: "adf"`, passing `description` as `{"type":"doc","version":1,"content":[...]}`. A panel is `{"type":"panel","attrs":{"panelType":"info"|"success"|"note"},"content":[paragraphs, bulletList]}`; inline code is a text node with `"marks":[{"type":"code"}]`, links `{"type":"link","attrs":{"href":...}}`, bold `strong`. Markdown `contentFormat` cannot express panels, and every read-back (MCP markdown/adf, `koda tool jira workitem view`) flattens them, so confirm the panels by looking at the issue in a browser.
- Cross-project links can fail with "No Link Issue Permission" when the target key was moved to another project (e.g. RDAZ-1451 → RDCAG-72); mention the key and URL in the description instead and tell Eduardo.
